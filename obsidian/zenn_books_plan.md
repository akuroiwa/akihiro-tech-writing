# Zenn Books 執筆計画 & 方針 (Zenn Books Plan)

本プロジェクトにおいて執筆する Zenn Book（開発ノートシリーズ）の確定ラインナップ、執筆順序、および各本の方針を以下に定義する。

---

## 1. Zenn Book 確定ラインナップ (3部作)

これまでの開発履歴と技術変遷に基づき、以下の3冊を「開発ノート」シリーズとして執筆する。

### 📚 開発ノート #1: 『chess-ant 開発ノート：泥臭い手作業からAIとの協業へ、チェスエンジン開発5年の軌跡（仮）』
* **対象ソフトウェア**: `chess-ant`, `chem-ant`, `mcts-solver`, `chess-classification`, `chem-classification`, `py-chessboardjs`
* **技術的テーマ**: 遺伝的プログラミング (GP) とモンテカルロ木探索 (MCTS) の融合、論文ベースの MCTS Solver 実装、Google Colab での勝敗予測モデル（Simple Transformers / PyTorch）の試行錯誤、`pywebview` と `chessboard.js` による GUI 構築、Python と JS 間の Promise パターン、非同期スレッド並行処理（GUI と探索エンジンのデカップリング）。
* **物語の重点**:
  * **なぜ作ったか**: DEAPのアリGPシミュレータを出発点に、チェスの問題解決シミュレータとして開発を開始。その後、化学構造探索（chem-ant）へと応用を広げ、最終的に独自のデスクトップGUI（py-chessboardjs）を求めた。
  * **苦労・失敗**: 手作業での泥臭い実装、AIの提案コードでの度重なる失敗、GUIスレッドと重い探索エンジン間の競合によるフリーズ（2025年の `EngineWorker` による解決までの2年越しの格闘）。
  * **AIとの協業**: 完全手作業から、2023年春に ChatGPT のアドバイスを得て `mcts-solver` の並列化に挑んだことを契機とした「AIとの出会い」。そして `py-chessboardjs` のデバッグでの ChatGPT / Bard との対話型デバッグへの発展。

### 📚 開発ノート #2: 『mcts-gen 開発ノート：AIエージェントと構築する汎用モンテカルロ木探索フレームワーク（仮）』
* **対象ソフトウェア**: `mcts-gen`（チェス、将棋、リガンド生成対応）
* **技術的テーマ**: UCT（モンテカルロ木探索）アルゴリズム、AIエージェント（LLM）を用いた「Policy Pruning（方策枝切り）」および価値予測、MCP（Model Context Protocol）によるAIツール化。
* **物語の重点**:
  * **なぜ作ったか**: `chess-ant` の遺伝的プログラミング (GP) エンジンを、現代的なAIエージェント（LLM）による評価・探索に置き換えて汎用化するため。
  * **苦労・失敗**: AIの探索空間の肥大化、応答速度のボトルネックと「Policy Pruning（方策枝切り）」による解決。
  * **AIとの協業**: `gemini-cli` をコマンドラインのAIエージェントとして開発に本格導入し、自律的なコード実装とツール作成を行ったプロセス。

### 📚 開発ノート #3: 『spec-craft 開発ノート：AIエージェントと実践する仕様駆動開発（仮）』
* **対象ソフトウェア**: `spec-craft`、`fpocket-snap`（CI/CDパッケージング）
* **技術的テーマ**: 仕様駆動開発 (SDD) の思想、Obsidian を用いたAIコンテキストの外部化（Single Source of Truth）、CI/CD自動化（Snapcraft & GitHub Actions）。
* **物語の重点**:
  * **なぜ作ったか**: 開発と並行したAIのコンテキスト共有、およびAIのトークン制限や迷走を防ぐために、Obsidian（戦略）と spec-kit（戦術）を繋ぐ必要があった。
  * **苦労・失敗**: spec-kit のフルサイクルによるAPIトークンの急激な消費、エージェントの作業分離と軽量化の設計。
  * **AIとの協業**: `antigravity-cli`（本エージェント）との協業による、仕様策定から実装までの開発プロセスの完全な構造化。

## 2. 執筆のロードマップ（優先順位）

時系列に沿った技術の変遷と、執筆のしやすさを考慮し、以下の順序で執筆を進める。

1. **第1弾: 『開発ノート #1 chess-ant』**
   * **理由**: すべての探索アルゴリズム開発、GUI開発、およびAIとの協業の出発点であり、個人開発の変遷からAIの登場までの歴史的なグラデーションを描くのに最適。
2. **第2弾: 『開発ノート #2 mcts-gen』**
   * **理由**: Book #1 で確立した探索エンジンとGUI連携を、さらに「AI拡張MCTS」へと進化させた第2ステップ。技術的にも最も興味深いテーマ。
3. **第3弾: 『開発ノート #3 spec-craft』**
   * **理由**: 現在進行形であり、これまでの開発プロセスの課題（トークン制限やAIの迷走）を解決するために誕生した集大成のツール。

## 3. 執筆プロセスの方針

1. **開発年表の埋め込み**:
   * 各本の「はじめに」または「開発の背景」の章に、[開発年表](file:///home/akihiro/文書/develop/git/akuroiwa/akihiro-tech-writing/obsidian/development_timeline.md)から抽出した時系列の日付や出来事を記載し、歴史的な正確性を持たせる。
2. **テンプレートの準拠**:
   * 原則として [Zenn Book 構成テンプレート](file:///home/akihiro/文書/develop/git/akuroiwa/akihiro-tech-writing/obsidian/zenn-books-template.md) の構成に沿って執筆する。
3. **対話型執筆**:
   * 毎回、新しい章を書き始める前に、対象となるソフトウェアの `dev-log/` のやり取り（ChatGPTやGemini等との当時の記録）や `dev-source/` のソースコードをAIが読み込み、ユーザーと打ち合わせを行ってから下書きを作成する。

## 4. 各本の詳細章立て案

### 📚 開発ノート #1: 『chess-ant 開発ノート：泥臭い手作業からAIとの協業へ、チェスエンジン開発5年の軌跡（仮）』

#### Ⅰ部: 孤独な試行錯誤とアルゴリズムへの挑戦（完全手作業の時代）
* **第1章: すべては1匹のアリから始まった（2019年〜2020年）**
  * 着想と計画：DEAPの遺伝的プログラミング (GP) シミュレータ `sim-chess` からの出発
  * 実行方法の違い：ファイルを直接起動するアプローチと、パッケージコマンドとしての呼び出し (`similarity-mcts` 等)
  * AlphaZeroの衝撃：`FlaskChess` へのモンテカルロ木探索 (MCTS) 組み込みと、最初の壁
* **第2章: Git管理の開始と「パスタコミット」の日々（2021年）**
  * `chess-ant` としての本格始動（2021年12月10日）
  * 手探りのコードベース構築と、個人開発特有のスパゲッティコード（パスタコミット）との戦い
* **第3章: 機械学習の導入と探索の深化（2022年）**
  * Google Colab をフル活用した `chess-classification` の試み
  * Simple Transformers/PyTorch による盤面勝敗予測モデルの実験と限界
  * チェスから化学構造探索 (`chem-ant` / `chem-classification`) への応用の芽生え
* **第4章: コア探索エンジンの独立と「収束」へのブレイクスルー（2022年後半）**
  * `mcts-solver` を別パッケージとして分離・独立させた理由
  * Winandsらの論文「Monte-Carlo Tree Search Solver」との出会い
  * 手作業での解法実装：枝切りアルゴリズムの導入による、ドラマチックな解的収束向上

#### Ⅱ部: AIという相棒の登場と、次世代GUIへの脱皮（AI協業の時代）
* **第5章: 最初のAI協業：ChatGPTと挑んだ並列処理（2023年春）**
  * 手作業の限界：MCTSの計算ボトルネックをどう突破するか
  * ChatGPTへの最初の相談と、並列化（マルチスレッド/マルチプロセス）に向けた長い試行錯誤（2023年4月19日〜）
  * `mcts-solver` の並列化実装における AI 提案コードと実稼働の調整
* **第6章: py-chessboardjs誕生：PythonとJavaScriptの架け橋（2023年後半）**
  * 独自のGUI環境を求めて：`pywebview` ＋ `chessboard.js` という選択
  * バックエンド（Python探索エンジン）とフロントエンド（JS）の連携設計
* **第7章: ChatGPT / Bard と格闘したJSデバッグ（2023年末）**
  * `chess_ant.main()` 呼び出しのエラーと、対話型チャットを壁打ちにした泥臭いデバッグ（※当時はエージェントでなくファイルを直接編集）
  * キャスリング処理やPGN読み込みにおける、JavaScript側の動作とPython側の連携バグの解決
* **第8章: 2年越しの解決：EngineWorkerでスレッド競合を根絶する（2025年10月）**
  * 画面がフリーズする！：GUIスレッドと重い探索エンジンの並行処理バグ
  * `CancelledError` と `EngineTerminatedError` に対する `EngineWorker` と asyncio イベントループを用いたデカップリング設計
  * 開発と並行したAIエージェントとの共同作業による、難解な競合状態（レースコンディション）の解消

#### おわりに：そして「汎用化（mcts-gen）」と「自動化（spec-craft）」へ
* チェス特化型AI開発を通じて得られた知見の総括
* 手作業でアルゴリズムを理解していたからこそ、AIを正しく導けたという実感
* 次なるステップ：AIエージェントによる汎用フレームワーク化（ノート#2へ続く）
