# Zenn Books 執筆計画 & 方針 (Zenn Books Plan)

本プロジェクトにおいて執筆する Zenn Book（開発ノートシリーズ）の確定ラインナップ、執筆順序、および各本の方針を以下に定義する。

---

## 1. Zenn Book 確定ラインナップ (3部作)

これまでの開発履歴と技術変遷に基づき、以下の3冊を「開発ノート」シリーズとして執筆する。

### 📚 開発ノート #1: 『py-chessboardjs 開発ノート：pywebviewとAIで挑んだチェスGUI連携開発（仮）』
* **対象ソフトウェア**: `py-chessboardjs`（および接続先である `chess-ant`、`mcts-solver`）
* **技術的テーマ**: `pywebview` による Python と JavaScript（`chessboard.js`）の双方向通信、Promise パターン、非同期スレッド処理（GUIと探索エンジンの並行稼働）、AIとの本格的な共同デバッグ。
* **物語の重点**:
  * **なぜ作ったか**: `chess-ant` 単体ではGUIがなく動作確認が困難だったため、手軽に動作確認ができる自前デスクトップGUIを求めた。
  * **苦労・失敗**: `pywebview` と `chess-ant` 探索処理とのスレッド競合によるGUIフリーズ、通信エラー。
  * **AIとの協業**: 初めてAI（ChatGPT）をデバッグパートナーとして本格的に迎え、複雑な並行処理の問題を解決したプロセス。

### 📚 開発ノート #2: 『mcts-gen 開発ノート：AIエージェントと構築する汎用モンテカルロ木探索フレームワーク（仮）』
* **対象ソフトウェア**: `mcts-gen`（チェス、将棋、リガンド生成対応）
* **技術的テーマ**: UCT（モンテカルロ木探索）アルゴリズム、AIエージェント（LLM）を用いた「Policy Pruning（方策枝切り）」および価値予測、MCP（Model Context Protocol）によるAIツール化。
* **物語の重点**:
  * **なぜ作ったか**: `chess-ant` の遺伝的プログラミング (GP) エンジンを、現代的なAIエージェント（LLM）による評価・探索に置き換えて汎用化するため。
  * **苦労・失敗**: AIの探索空間の肥大化、応答速度のボトルネックと「Policy Pruning（方策枝切り）」による解決。
  * **AIとの協業**: `gemini-cli` をコマンドラインのAIエージェントとして開発に本格導入し、自律的なコード実装とツール作成を行ったプロセス。

### 📚 開発ノート #3: 『spec-craft 開発ノート：AIエージェントと実践する仕様駆動開発（仮）』
* **対象ソフトウェア**: `spec-craft`、`fpocket-snap`（CI/CDパッケージング）
* **技術的テーマ**: 仕様駆動開発 (SDD) の思想、Obsidian を用いたAIコンテキストの外部化（Single Source of Truth）、CI/CD自動化（Snapcraft & GitHub Actions）。
* **物語の重点**:
  * **なぜ作ったか**: 開発と並行したAIのコンテキスト共有、およびAIのトークン制限や迷走を防ぐために、Obsidian（戦略）と spec-kit（戦術）を繋ぐ必要があった。
  * **苦労・失敗**: spec-kit のフルサイクルによるAPIトークンの急激な消費、エージェントの作業分離と軽量化の設計。
  * **AIとの協業**: `antigravity-cli`（本エージェント）との協業による、仕様策定から実装までの開発プロセスの完全な構造化。

## 2. 執筆のロードマップ（優先順位）

時系列に沿った技術の変遷と、執筆のしやすさを考慮し、以下の順序で執筆を進める。

1. **第1弾: 『開発ノート #1 py-chessboardjs』**
   * **理由**: すべてのGUI・AI協業の出発点であり、過去の「失敗談」や「設計判断」の記憶が明確であり、ドキュメント化の土台として最適。
2. **第2弾: 『開発ノート #2 mcts-gen』**
   * **理由**: Book #1 で確立した探索エンジンとGUI連携を、さらに「AI拡張MCTS」へと進化させた第2ステップ。技術的にも最も興味深いテーマ。
3. **第3弾: 『開発ノート #3 spec-craft』**
   * **理由**: 現在進行形であり、これまでの開発プロセスの課題（トークン制限やAIの迷走）を解決するために誕生した集大成のツール。

## 3. 執筆プロセスの方針

1. **開発年表の埋め込み**:
   * 各本の「はじめに」または「開発の背景」の章に、[開発年表](file:///home/akihiro/文書/develop/git/akuroiwa/akihiro-tech-writing/obsidian/development_timeline.md)から抽出した時系列の日付や出来事を記載し、歴史的な正確性を持たせる。
2. **テンプレートの準拠**:
   * 原則として [Zenn Book 構成テンプレート](file:///home/akihiro/文書/develop/git/akuroiwa/akihiro-tech-writing/obsidian/zenn-books-template.md) の構成に沿って執筆する。
3. **対話型執筆**:
   * 毎回、新しい章を書き始める前に、対象となるソフトウェアの `dev-log/` のやり取り（ChatGPTやGemini等との当時の記録）や `dev-source/` のソースコードをAIが読み込み、ユーザーと打ち合わせを行ってから下書きを作成する。
