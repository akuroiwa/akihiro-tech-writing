---
title: "第8章：2年越しの解決：EngineWorkerでスレッド競合を根絶する（2025年10月）"
---

2023年末に一旦はプレイ可能となった `py-chessboardjs` でしたが、2025年に入り、探索エンジンの強化とアプリケーションの本格運用に伴って、無視できない深刻な問題が浮き彫りになりました。それは、「UI操作時のスループットの競合とアプリケーションの突然のクラッシュ」でした。

---

## 思考中に動かすとクラッシュする

探索エンジンが必死に最善手を計算している最中に、ユーザーが「待った（指し手を戻す）」をかけたり、「盤面をリセット」したり、あるいは「対局を途中で終了してウィンドウを閉じる」といったUI操作を行うと、コンソールに以下のエラーが吐き出され、アプリケーションがフリーズまたはクラッシュする現象が発生しました。

* `concurrent.futures.CancelledError`
* `chess.engine.EngineTerminatedError`

原因は明らかでした。
`pywebview` が立ち上げるAPIスレッドと、思考エンジン（`chess-ant` や `stockfish` など）のプロセス通信を行う非同期 asyncio イベントループが、同一のスレッドコンテキスト上で競合していたのです。

エンジンが重い思考処理を実行している間、UIスレッド全体の処理がブロックされ、画面が一時的にフリーズしていました。さらに、そのフリーズ中にユーザーがボタンを連打するなどして蓄積されたイベントが、エンジンの思考キャンセルのシグナルと衝突し、例外を適切にハンドリングできずにクラッシュしていたのです。

---

## AIエージェントとの「仕様駆動開発」による解決

この時、開発体制には劇的な進化が起きていました。

2023年の「ブラウザ経由でコピペするチャットAI」とは異なり、2025年10月には、開発プロジェクトのディレクトリ構造を直接読み解き、テストから実装までを自律的にこなす **AIエージェント** が私の開発パートナーになっていました。

私たちは、仕様駆動開発 (Specification-Driven Development: SDD) に基づき、このバグを根本解決するための詳細な仕様書（`specs/003-fix-engine-concurrency/spec.md`）とタスク設計書を作成しました。

AIエージェントとの協業により、以下のアーキテクチャへのリファクタリングを実施しました。

1. **`EngineWorker` クラスの導入**:
   `pywebview` のAPIスレッドから完全に独立した、専用のバックグラウンドワーカー（ワーカースレッド）を立ち上げ、その内部で独自の asyncio イベントループを実行する。
2. **非同期デカップリング（疎結合化）**:
   UIから指示を受け取る `Api` クラスは、直接思考エンジンを叩くのではなく、スレッドセーフなキューを介して `EngineWorker` に指示を投げ、結果を非同期でJS側に通知する。

これにより、ユーザーが思考中にどのような操作を行っても、`EngineWorker` がバックグラウンドで思考プロセスを安全にキャンセル（あるいは再起動）し、UIスレッドが一切フリーズしない極めて堅牢な非同期協調動作が実現しました。

2025年10月25日、この根本解決は以下のコミットとしてリポジトリにマージされました。

* **Commit Message**: `feat: Implement robust engine concurrency and PyPI workflow` (Commit: `5df5df1`)

## GitHub Actions と PyPI への自動リリース

このバグ修正と同時に、プロジェクトを外部の開発者も手軽にインストールして利用できるようにするため、PyPI (Python Package Index) への自動デリバリー環境を整備しました。

GitHub にタグをプッシュすると、GitHub Actions が自動的にトリガーされ、TestPyPI および本番の PyPI にパッケージが自動ビルド・デプロイされるワークフローを構築しました。

手作業でのリリース作業や、セキュリティキーの漏洩リスクを排除する「Trusted Publishing（ID連携認証）」を導入し、個人開発でありながら、一流のオープンソースソフトウェアと同等の CI/CD 自動化体制を確立することができたのです。
