2023年春、`chess-ant` プロジェクトは重要な転換点を迎えます。それは、「開発者としてのAIとの本格的な協業」の始まりでした。

---

## 探索速度の壁と並列処理の難問

MCTS Solver の導入によって探索精度は向上したものの、探索の実行速度には依然として不満がありました。Python という言語の性質上、GIL (Global Interpreter Lock) の制限があり、単純なマルチスレッド化ではCPUのマルチコア性能をフルに引き出すことができません。

チェスの実戦時間内で十分な深さまで読み切るためには、探索処理を並列化（Parallelization）することが不可欠でした。

しかし、モンテカルロ木探索の並列化は一筋縄ではいきません。
スレッド同士が探索中の同一のゲーム木を同時に書き換える「木並列化 (Tree Parallelization)」は、データ競合を防ぐためのロック (Lock) 管理が非常に難しく、デッドロックや処理速度の低下（ロック競合によるオーバーヘッド）を引き起こしがちです。

当時の私は、この複雑なマルチスレッド・マルチプロセス処理の実装に行き詰まっていました。

---

## 2023年4月19日、最初の「AI協業」

このボトルネックを突破する糸口を与えてくれたのが、当時一般に広く普及し始めていた OpenAI の **ChatGPT (GPT-4)** でした。

それまでの「自分で書籍やウェブサイト、オープンソースのコードを調べて手作業で実装する」スタイルから、「複雑な並列処理の設計について、AIに設計相談を持ちかける」という新しい開発スタイルへのシフトです。

2023年4月19日、私は並列化処理のプロトタイプをマージし、以下のコミットを残しました。

* **Commit Message**: `Parallel processing is possible thanks to OpenAI's ChatGPT advice.`

これが、私の開発記録における最初期の「AIへの謝辞」となりました。ChatGPT は、並列化の設計案や、Python の `multiprocessing` モジュールを用いた実装例を提示し、暗闇の中に進むべき道筋を照らしてくれました。

---

## 終わらない試行錯誤と「チャットAI」の限界

しかし、歴史を美化するわけにはいきません。当時のコミットログを見ると、AIが提示したコードによって並列処理が一発で解決したわけではないことがはっきりと分かります。

* `2023-04-19`: `Parallel processing is possible thanks to OpenAI's ChatGPT advice.` (最初の並列化着手)
* `2023-04-21`: `Parallelization.` (さらなる修正)
* `2023-05-25`: `Parallelization of selectNode_num().` (特定メソッドの並列化調整)
* `2023-05-28`: `First aid. Is there a problem with parallel processing?` (並列処理のバグ発覚、応急処置)

4月19日の「ChatGPTのアドバイス」は、あくまで長い試行錯誤の入り口に過ぎませんでした。
当時のAIとのやり取りは、現在（2026年）の `antigravity-cli` のようにエージェントがワークスペースのファイルを直接読み込み、実行テストを繰り返して自律的にデバッグしてくれるものではありませんでした。

ブラウザのチャット欄にエラーメッセージやコードの断片を貼り付け、AIがもっともらしく提案したコードを手動でコピペし、動かしてみてはフリーズし、再びエラーログをコピーしてAIに問いかけるという、非常に非効率な「壁打ち」でした。

特に、コンテキストマネージャ（`with statement`）を用いたロックの取得や、スレッド間でのゲーム状態（`board` オブジェクト）の共有において、AIの提案したコードは多くのレースコンディション（競合状態）やデッドロックを引き起こしました。

この時期、私は Python 中心の開発者として、JavaScript の非同期処理に不慣れでした。2023年4月28日には、ChatGPT に Promise の仕組みそのものを質問しています。`pywebview` が Python の処理結果を JavaScript へ Promise として返すという仕組みを理解したことで、Python と JavaScript の連携設計がようやく腑に落ちたのです。

それでも、孤独にアルゴリズムと戦っていた時代とは異なり、「自分のコードの意図を正確に理解し、技術的な対話ができる相手がいる」ということ自体が、精神的にも技術的にも大きな支えとなりました。約1か月にわたる泥臭い試行錯誤の末、`mcts-solver` の並列化ロジックは実用的な安定性を獲得したのです。
